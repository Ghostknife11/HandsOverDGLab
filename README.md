# HANDS OVER Demo × 郊狼联动

版本 0.1.3（公开预览版）。手机 DG-LAB 4 APP 设置 A、B 通道上限，电脑按“上限 × 结果比例”设置实际输出强度，并控制波形和时长。适用于郊狼 3.0。

## 快速使用

1. 使用 Windows 10/11 x64，退出游戏并运行发布包中的 `安装模组.cmd`。首次会从 BepInEx 官方下载固定 build 790（约 34 MB），校验 SHA-256 后再安装。默认游戏目录是 `G:\SteamLibrary\steamapps\common\HANDS OVER Demo`。
2. 运行 `启动联动.cmd`（或 `app\HandsOverDGLab.exe`）。发布包已带 Python，不需要系统 Python；若提示缺少 VC++ 运行库，按提示从[微软官方](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)安装 x64 v14 运行库。
3. 手机 APP 先连接郊狼 3.0，再在电脑生成二维码，用手机扫码。默认选择 DG-LAB 4；旧连接入口可选择“兼容扫码”。切换方式后重新生成二维码，旧配对不再有效。
4. 在手机设置 A、B 上限，等待电脑出现设备、当前强度和手机上限。电脑显示每类反馈的预计实际数值；上限和静音由手机管理。
5. 无论游戏是否运行，均可点击“测试假牙”或“测试真牙”。手动测试不要求“启用联动”，也不要求进入对局。设备必须已连接。
6. 设备连接就绪并读到所选通道上限后，自动打开“启用联动”，无需每次手动开启；重新连接设备后也会自动开启。连接本身不会发送刺激，进入对局且本人按压出现结果时才触发。暂停、退出对局或游戏断开，只停止游戏触发的反馈，不取消独立的手动测试。游戏重新连接后继续等待新事件，不重播旧事件。
7. 反馈结束后，本次输出强度归零。“停止输出”会清理两路任务、将本程序控制的通道归零并关闭联动。关闭控制台、断开手机或切换设备也会清理输出；重连不补播旧事件。

手动关闭联动或按下“停止输出”后，普通强度/设备状态更新不会再次自动打开联动；可手动开启，或在下一次重新连接手机设备时自动开启。只有手机扫码配对、蓝牙设备尚未连接时，会继续等待设备就绪。

请在退出游戏后安装或更新插件。首次启动游戏时 BepInEx 会生成互操作缓存，耗时可能比平时长。

## 默认反馈

| 项目 | 假牙 / 假切 | 真牙 / 真切 |
| --- | --- | --- |
| 对应结果 | 普通按压、保护卡生效 | 机关、陷阱卡生效 |
| 手机通道上限比例 | 20% | 100% |
| 时长 | 0.3 秒 | 1 秒 |
| 波形 | 官方“气泡” | 官方“气泡” |

比例范围 0～100%，时长 0.1～10 秒，步长 0.1 秒。A、B 可选任一路或同时输出。调整后保存应用；点击手动测试也会应用当前面板参数。

实际强度 = 向下取整（手机当前上限 × 比例 / 100）。A、B 分别计算。例如 A 上限 100、B 上限 80：假牙 20% 对应 A=20、B=16，真牙 100% 对应 A=100、B=80。计算与测试前的通道当前数值无关。0% 不输出。

波形采样保持原样，不再同时打折。电脑不修改手机上限、舒适限制或静音设置；APP 仍可能按自身的冷启动、静音、连接和设备限制约束最终输出。若手机没有上报某个所选通道的上限，程序拒绝输出，不猜测为 100。

V4 先将所选通道基础强度归零，再并行下发指定数值、指定时长的临时强度任务和原始波形任务。临时强度到期由 APP 自动归零。兼容模式设置实际强度值，电脑在反馈结束时发送归零和清空指令；建议优先使用 V4 的 APP 端定时机制。

新事件替换正在播放的反馈，时长不累加。只监听本机玩家角色，同一按压结果去重，不额外发送断手、死亡或回合开始反馈。

## 二维码与连接

- DG-LAB 4 默认服务器：`wss://trex.dungeon-lab.cn/v4`。二维码保留 `/v4` 路径，当前官方服务器对 `/v4/` 返回 404，不能额外增加尾部斜杠。
- 兼容扫码默认服务器：`wss://ws.dungeon-lab.cn`。兼容二维码采用官方 `DGLAB-SOCKET` 格式。
- `wss` 是加密 WebSocket；`ws` 是未加密连接。协议须与中继服务器一致，不要直接删掉 `s`。
- 在“服务器设置”可修改地址。扫码不成功时先重新生成，避免使用已断开会话的二维码。
- 系统代理可能影响网络连接；本版本未修改你的代理配置。主窗口图片空白的刷新错误已修复，两种模式均无需先放大才显示。
- 若配对成功但无输出，先查看手机是否已连接蓝牙设备、是否静音、通道上限是否为 0 或未上报，以及电脑是否选中了对应通道。

兼容模式的官方公网中继按一秒、10 帧转发，短反馈尾部补静默帧，长反馈分秒发送。每个有效波形帧仍为 100ms，网络传输和手机调度会影响实际开始时刻。清空指令后等待 150ms 再发送新波形。V4 使用 APP 原生任务时长与替换机制，优先使用 V4。

早期调试版兼容适配存在错误：把波形装入数字 type=4 消息，中继可能将其解释为 A 通道归零。现已改用官方 SDK 的 `clientMsg` 波形发送，数字 type=4 只用于明确带通道号的 `clear`。本版按用户最新要求，使用数字 type=3 设置“手机上限百分比”对应的实际强度；反馈后归零。

## 日志与配置

- 电脑配置：`%LOCALAPPDATA%\HandsOverDGLab\settings.json`
- 电脑日志：同目录 `desktop.log`，界面可打开目录。最多保留三个轮转备份。
- 启动异常：同目录 `startup-error.log`
- 游戏事件：游戏目录 `BepInEx\HandsOverDGLab.events.jsonl`
- 加载器日志：游戏目录 `BepInEx\LogOutput.log`
- 本机游戏通信：`127.0.0.1:17896`，不监听外部网卡。

只保存参数，不保存可复用配对身份。每次连接取得新的会话标识。

## 安装与卸载

公开发布包必须保持 `app`、`plugin`、`scripts` 文件夹结构。加载器不镜像在包内，首次安装从官方获取并验证固定归档；下载缓存位于 `%LOCALAPPDATA%\HandsOverDGLab\downloads`。需要离线安装或使用接口兼容的修改版时，可自行准备加载器目录，再传入 `-FrameworkPath`。双击相应 cmd 即可运行。模组本身无需管理员权限，前提是当前账户有游戏目录写入权；微软运行库安装器另按其要求运行。

脚本会先检查冲突，记录新增文件及 SHA-256。遇到其他来源的不同文件会拒绝覆盖。升级仅覆盖本模组记录且未被用户修改的文件。

退出游戏后运行 `卸载模组.cmd`。卸载只移除安装记录中内容未被修改的文件，保留原游戏、原来存在的相同文件、配置、日志及运行生成的缓存。用户修改过的模组文件会保留，并保留对应安装记录。不会递归删除整个 BepInEx 目录。

其他游戏路径可在 PowerShell 调用 `scripts\Install.ps1 -GamePath '你的游戏目录'` 或相应卸载脚本。仅安装桌面控制台不需要把它复制进游戏目录。

## 源码构建

源码位于仓库根目录。使用 Python 3.13 和 .NET SDK。官方 SDK 已按固定提交保存在 `desktop\vendor`，附 GPL v3 许可证和来源记录，不从未核实的第三方包获取。

1. 运行依赖见 `requirements.txt`，打包依赖见 `requirements-build.txt`，连同二维码回读测试依赖见 `requirements-dev.txt`。开发时安装 `requirements-dev.txt`。
2. 运行 `scripts\bootstrap.py` 获取固定版本加载器。BepInEx 6.0.0-be.790+4e98359。
3. 安装加载器并启动游戏一次，生成 `BepInEx\interop`；退出游戏。
4. 运行 `python scripts\build_release.py`，会构建插件、打包桌面运行时、核对原生文件来源，生成 Windows ZIP、对应应用源码 ZIP、LGPL 框架源码 ZIP、校验清单及许可证目录。构建流程不会把整个外部框架或系统 CRT 复制到公开包；详见[发布说明](docs/PUBLISHING.zh-CN.md)。
5. 运行 `python -m unittest discover -s tests -v`。`scripts\probe_relay.py` 是独立模拟手机的公网检查，不连接实际设备、不读取现有用户配对。

官方依据：[DG-LAB 4 SDK](https://github.com/dungeonlab-open/dglab-kit/blob/main/README_CN.md)、[固定提交 Python SDK](https://github.com/dungeonlab-open/dglab-kit-python/tree/4cce771c0fd93d043f3e83bbb0467e4197cde62e)、[郊狼 3.0 协议](https://github.com/dungeonlab-open/dglab-bluetooth-protocol/blob/main/coyote/README_CN.md)、[兼容中继源码](https://github.com/dungeonlab-open/dglab-websocket-simple/tree/main/socket/v2/backend/src)。
